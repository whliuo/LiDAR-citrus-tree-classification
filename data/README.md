# Inputs

The point clouds are distributed separately as **segtree.7z**. Download URL,
archive checksum and data terms are pending owner publication.

Extract the folders directly below `data/segtree/`, or supply their parent with
`python main.py extract --data-dir PATH`. The archive should contain the
**current regraded `segtree_height` observations**, not the historical missing
six-class `segtree` input referenced by early scripts.

Filename convention:

```text
Class_TreeID_FieldID_TreeType_Altitude_Sensor.las
1_3101_3_4_020_1.las
```

Final labels are integers 0–4. `TreeID` is a string (leading zeroes matter).
Fields 1, 2, 3, 4 correspond to DKSB, PBOV, BTMS, BTMN. `TreeType` is retained
as a string and can contain underscores. Sensor tokens are `1`/`L1` and
`2`/`H300`. LAS and LAZ are accepted recursively below each folder.

`TreeKey = FieldID|TreeID|TreeType` identifies a biological tree across flight
heights and sensors. `(Source, Altitude, TreeKey)` identifies an observation.
The extraction output preserves these identifiers, class, sensor token and
source filename; source paths are relative to the supplied data root.
Neither field ID nor tree type is used as a classifier feature.

`observation_order.csv` contains identifiers, labels and relative filenames
derived from the final t02 extraction tables. Its row order reproduces t03's
training-row order even when worker completion order changes. It contains no
point coordinates. Unlisted observations are deterministically ordered after
known observations; archived profile controls are restricted to the original
60-m identity/label cohort and matching profile values.

`reference/` contains small archived t03 result tables for regression checks
and the three Profile20 controls carried forward into the final audit.
`profile_benchmarks.csv` identifies those rows as archived. The controls come
from manuscript V2 (LR/CNN) and V9G (RF), as already assembled by t03. They are
not generated by rerunning the midpoint classifier.

`context/visual_ratings.csv` contains only R1–R4 from the finalized visual
repeatability workbook's Tree_Level sheet (882 rows). `context/qpcr.csv`
contains field, hlb and qpcr from the finalized qPCR workbook (1,073 rows).
Unneeded row IDs and spreadsheet-derived columns were omitted. These cohorts
are unlinked to the LiDAR tree table. The qPCR input has no class-0 viable-leaf
samples; the original summary convention is preserved.

Optional raw-density inputs belong in `data/rawdata/` or an external read-only
directory supplied with `--input-dir`. These are full flight LAS files,
not segmented trees. Raw polygon shapefiles and clipping are upstream of this
release: users start with the already segmented archive.
